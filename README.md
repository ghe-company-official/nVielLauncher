# nVielLauncher

official nviel repo, pllslllllllllllllllllllllllssss join the tg: @nvielclient

Чёрно-белый лаунчер Minecraft на WPF (.NET 8) для Fabric 1.21.4: оффлайн-вход,
моды с Modrinth, сборки `.mrpack`, сервера, профили, обучение и диагностика падений.

## Возможности

- один экземпляр лаунчера: повторный запуск показывает уже открытое окно;
- включение и выключение установленных модов (файл переименовывается в `.jar.disabled`);
- nVielRE — отдельный режим восстановления: Java, файлы Minecraft/Fabric, обязательные
  моды, журнал операций и быстрые действия;
- автообновление из приватного GitHub Releases с проверкой размера, PE-заголовка, версии и SHA-256.

## nVielRE

Открывается кнопкой **nVielRE** в боковой панели или в **Настройки → Восстановление**.
Тот же exe можно запустить с флагом `--re`. Режим не запускает игру и использует отдельный
single-instance mutex, поэтому может работать параллельно с обычным лаунчером.

## Обновления

**Настройки → Обновления → Проверить**. Лаунчер обращается к последнему GitHub Release
репозитория, указанного в **Настройки → Источник обновлений**. Если поле репозитория
пустое, используется приватный `ghe-company-official/nVielLauncher-releases`.

## Закрытый репозиторий обновлений

Для exe со встроенными модами используйте отдельный **приватный** репозиторий релизов:

1. Создайте приватный репозиторий, например `nVielLauncher-releases`.
2. Создайте fine-grained GitHub token только для этого репозитория:
   - для лаунчера достаточно `Contents: Read`;
   - для публикации релизов нужен `Contents: Read and write` (его в лаунчер не вставляйте).
3. В лаунчере откройте **Настройки → Источник обновлений**, укажите `owner/repo`,
   вставьте token и нажмите **Сохранить**.
4. Соберите `dist\nVielLauncher.exe`, создайте Release с тегом версии (например, `v1.0.1`)
   и прикрепите `nVielLauncher.exe` как asset.

Лаунчер скачивает asset через GitHub API. Токен передаётся только хостам GitHub;
при редиректе на подписанный storage-URL он не пересылается. Токен хранится локально
в зашифрованном виде (Windows DPAPI, текущий пользователь), не пишется в логи и не
попадает в git. Если токен не сохранён в настройках, лаунчер автоматически пробует
переменные окружения `NVIEL_UPDATE_TOKEN`, `GITHUB_TOKEN`, `GH_TOKEN`, а затем
Git Credential Manager. Поэтому на машине с уже настроенным git обновления работают
без ручного ввода токена. Публичный исходный репозиторий по-прежнему не содержит
`.jar`, `.exe` и секретов.

Перед установкой проверяются размер, PE-заголовок, имя продукта, версия файла и SHA-256
(если GitHub вернул digest). Затем exe заменяется через отдельный PowerShell-помощник и
лаунчер перезапускается.

> Публичный исходный репозиторий `nVielLauncher` не используется для обновлений и не
> должен содержать exe/jar. Релизы и exe со встроенными модами хранятся только в
> приватном репозитории релизов.

## Запуск из исходников

Нужен .NET 8 SDK (Windows).

```powershell
dotnet build src\nVielLauncher\nVielLauncher.csproj -c Release
src\nVielLauncher\bin\Release\net8.0-windows\nVielLauncher.exe
```

## Один автономный exe

```powershell
.\build-release.ps1
```

Результат — `dist\nVielLauncher.exe` (self-contained, .NET у пользователя не нужен).
При запуске он устанавливается в `%APPDATA%\.nviel\app`, создаёт ярлыки и удаляет
исходный файл из «Загрузок».

## Моды

- `mods/*.jar` — пользовательские моды, в репозиторий не входят.
- `src/nVielLauncher/embedded/*.jar` — обязательные встроенные моды, тоже не входят.

Обе папки перечислены в `.gitignore`. Без них проект собирается, но не устанавливает
обязательные моды. Подробнее — `src/nVielLauncher/embedded/README.md`.

## Где хранятся данные

- Настройки и логи: `%LOCALAPPDATA%\nViel Launcher`
- Игра и установленный лаунчер: `%APPDATA%\.nviel`
